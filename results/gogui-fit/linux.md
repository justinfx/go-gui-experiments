# go-gui v0.96.0 (apps/gogui) on Linux (container run, linux/arm64, Ubuntu 24.04)

Harness: `linux/`. Logs and screenshots: `results/gogui/linux/` (`x11/` Xvfb+openbox, `sway/` sway headless Wayland, `wayland/` weston headless, `x11-theme/` the live system-theme check).
Timings and visual sharpness not measured. Screenshots are of the app window only (zenity dialogs captured by their own window id on X11 and their own rectangle on sway).

## How it runs on Linux (read this first)

go-gui draws everything itself with OpenGL ES through EGL. No GTK, no webview. The X11 path speaks the X protocol in pure Go (`github.com/jezek/xgb`, `gui/backend/gl/runapp_x11.go`); the Wayland path has its own client (`gui/backend/internal/wl`). Native libraries are opened at run time through purego, not linked:

- `libEGL.so.1` (required, `gui/backend/gl/egl_linux.go:73`), plus whatever Mesa's EGL pulls in (`libEGL_mesa`, `libgbm`, `libdrm`, `libGLdispatch`, `libxcb*` / `libX11-xcb`); seen in `/proc/<pid>/maps` (`x11-maps.log`, `sway-maps.log`).
- Wayland: `libwayland-client.so.0`, `libwayland-egl.so.1`, `libxkbcommon.so.0`; `libdecor-0.so.0` optional (window frame on compositors that draw none, `gui/backend/internal/decor/decor.go:78`); `libgtk-3.so.0` only with `RTLD_NOLOAD` (reads the prefer-dark setting when the libdecor GTK plugin already loaded GTK, `decor/gtk.go:66`).
- Subprocesses, not libraries: `zenity` or `kdialog` (file dialogs, `gui/backend/filedialog/dialog_linux.go:25-30`), `notify-send` (notification, `gui/backend/internal/nativehost/notification_other.go:28`), `gsettings get/monitor` (system light/dark, `gui/backend/gl/appearance_x11.go`), `xdg-open` (open URI).

`make build` is a plain `go build` with the default `CGO_ENABLED=1`; the binary is 31.8 MB and `ldd` lists only `libc.so.6` (`ldd.log`). Nothing beyond libc is needed at link time; at run time the target needs Mesa/EGL and, for full integration, zenity (or kdialog) and libnotify-bin.
In the container EGL ran on llvmpipe (no `/dev/dri`); the UI rendered correctly.

## Findings (framework gap vs app bug vs container limit)

1. **Ctrl+Q does not quit on Linux (X11 and sway). Classification: app gap caused by a framework gap.** On macOS Quit comes from the native menubar's app menu. go-gui has no Linux menubar (`menu_other.go:18` no-op), and the app registers no quit command of its own (`view.go:853-865` lists export, import, copyrow, view.table, view.cards, reload, focus.search, host). The app already has `plat.Quit` (`platform_desktop.go:75-77`, `gui.DispatchQuitRequest`), so one more `cmd("quit", ..., gui.KeyQ, m, ...)` would fix it. Window close via the WM works.
2. **No menu bar on Linux. Classification: framework gap.** `NativeMenubarCfg` is macOS only and go-gui offers no in-window menubar fallback; the app does not draw one. Functionality is still reachable (buttons, shortcuts), but About has no entry point on Linux and the shortcuts are not discoverable.
3. **No `WM_CLASS` on X11 and null `app_id` on Wayland. Classification: app bug (small).** go-gui supports it (`gui/window_cfg.go:49-53`, `WMClass`, defaulted from `AppInfo.ID`; set in `backend/gl/icon_x11.go:122` and `wayland_shell_linux.go:173`), but `apps/gogui/main_desktop.go` sets neither. Effect on a real desktop: the window does not match a `.desktop` file (no taskbar icon or grouping, GNOME shows a generic icon).
4. **File dialogs depend on zenity or kdialog at run time. Classification: framework design, works.** With either installed, the dialog is a separate process, not modal or transient for the app window, with the generic `Files` filter label. Without them go-gui falls back to its own in-window browser, which worked; no portal (`org.freedesktop.portal.FileChooser`) path exists, so Flatpak-style sandboxes and GNOME's portal chooser are not used.
5. **Notification uses `notify-send`. Classification: framework design, works.** Arrives on D-Bus and in dunst; shows as app `notify-send`, not GGUIX. Needs libnotify-bin on the target.
6. **Reveal opens the parent folder, file not selected. Classification: framework gap (no API) plus app choice (core helper).** Same as the other non-MyGo apps.
7. Container limits: weston headless has no seat (app stays alive, not inspectable); no XWayland in sway, so `GOGUI_WAYLAND=0` under sway has no X server; no GPU (llvmpipe). zenity and `libxkbcommon-tools` (`xkbcli`, needed by `wlinput.py`) were not in the image and were installed into the running container only (zenity to exercise the external-dialog path after the fallback path was recorded). dunst crashed once in the weston session (unrelated).
8. Observed, not compared with macOS: the Host Info dialog's buttons (`Reveal Last Export`, `Close`) and the long `Note` value render past the dialog card's right edge (`x11-host-dialog.png`, same on sway). Cause not isolated (could be Linux font metrics with DejaVu); not classified.
